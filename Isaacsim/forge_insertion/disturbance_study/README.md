# 自动配对扰动敏感性实验

目标：先找出**当前零随机化版第200轮模型**最怕的扰动，再自动让**原随机化版第200轮模型**复用完全相同的条件和配对样本，比较两个模型的抗扰能力。不重新训练。
模型位置、SHA256及官方代码指纹在 `lock.json` 中；任何变更会停止实验，避免混用结果。

## 一条命令启动

```bash
cd /home/masais/Xinyu/Isaacsim/forge_insertion/disturbance_study
./start.sh
```

启动后可以关闭终端，不需要手动切换条件或另开多个 terminal。`pipeline.log` 持续保存日志，`status.json` 保存当前阶段、条件、seed；第一阶段生成 **`RESULTS.md`** 及 `episodes.csv`；随后自动重放第二模型并生成 **`MODEL_COMPARISON.md`**，且在主报告中加入链接。两阶段都完成后 status 才变为 complete。
若被中断或失败，检查日志并解决原因后再次运行同一命令，会校验并跳过已完成任务。不会重复启动第二个同时运行的实验。`./run.sh` 可选择在前台运行同一流程。
失败时不会生成伪造的最终结论；失败任务的 `failure.txt`、`console.log` 会保留。单个仿真进程15分钟超时，进程及其子进程会退出；主流程停止等待排查。没有自动放宽物理阈值或改变模型的重试逻辑。

## 实验设计（预先确定）

先运行固定环境 zero 和完整随机化 full 两个基准，再对每类做仅开启和仅关闭：

| 类别 | 单项 |
|---|---|
| 初始位姿 pose | base_position、base_yaw、hand_position、hand_orientation、grasp_offset |
| 物理参数 physics | mass、friction |
| 控制参数 control | gains、ema、position_threshold、rotation_threshold、dead_zone |
| 观测 observation | hole_observation、tip_position_noise、tip_rotation_noise、force_noise |
| 其他 other | contact_threshold、quaternion_sign |

共18项。初筛5 seeds（0–4），每seed每条件128个同步环境，每环境完整1个回合。两种模式：

- 仅开启：其他因子固定为零随机化版的值，只恢复该类/项的原随机分布。
- 仅关闭：其余因子均使用原随机分布，仅把该类/项固定为零随机化版的值。

关闭时有标称值则保留标称值，无标称值沿用既有中点约定：质量17.5g；EMA0.0625；base静摩擦0.75；接触阈值7.5N；死区[2.5,2.5,2.5,0.5,0.5,0.5]；四元数符号+1。
奖励、控制和判据的**公式/实现**不改；控制参数、奖励相关接触阈值是明示的实验自变量，不可能测试它们的扰动同时又要求它们的数值完全不变。

定义：

```
开启下降 = success(zero) − success(on)
关闭恢复 = success(off) − success(full)
敏感性分数 = (开启下降 + 关闭恢复) / 2
```

按分数排序，同时报告两个方向，避免掩盖交互作用。分数不是相加为100%的“贡献占比”，负值也保留。

前两名差距小于5个百分点，或者差值的配对95%区间包含0，则所有该阶段条件共同追加5个seed，最多15个seed。达到上限仍模糊时，保留“未明确区分”的结论，按点估计第一名继续探索性细分。

选择类别第一名后，对该类别所有单项重复上述流程。其他类别不继续拆分，因此如果类别排名模糊，不能宣称找到了全体18项中的唯一最大项。

筛选后使用**未参与筛选的100–104 seeds**，对入围前两类和前两单项的开/关及两个基准做确认。独立确认排名可与筛选相反；报告不会强行改成确定结论。

## 真正配对，而不仅是 seed 相同

- `samples/n128_seed*.npz` 在对应seed的任何仿真开始之前生成，包含所有条件共同使用的扰动和策略标准正态样本。每个因子使用 SHA256 派生的独立随机流，记录逐流指纹。
- 初始扰动按env_id索引；IK候选按attempt和env_id索引（最多32次，超限失败），不会因为另一个环境重试而错位。
- reset观测噪声与正式rollout时间段分离，IK耗时不会推进rollout噪声序列。reset阶段最多2048次中间状态计算，超限失败。
- 每个正式控制步均使用同一对应位置的噪声样本。关闭噪声只是将幅度设为零，并不移动其他流。
- 动作保留原有 `Normal(mu,sigma)` 随机采样、裁剪和RNN更新；独立预生成epsilon并使用 `mu + sigma * epsilon`。相同epsilon不意味着不同观测下动作相同。
- 质量/惯量更新保留原公式；摩擦保留官方128个材料桶与每形状桶分配的机制。
- 使用独立适配类，只把官方3个方法中的随机采样替换为样本查表；生成后的可读方法位于 `paired/adapted*.py.txt`。未修改官方代码或原训练任务。
- 因随机源改为预生成配对样本，本次基准会重新测量，不能直接把之前的23.44%或100%作为本次分母。

## 指标和统计

主指标：回合结束最终成功率。辅助指标：曾成功但未保持、最终插入深度、最终XY误差、回合平均腕力、每回合最大平滑腕力的P95。完整数据逐回合保留。

95%区间使用2000次配对分层bootstrap：先按seed再按环境编号重采样，各条件共同使用索引。筛选阶段区间是探索性的，不是做过多重比较校正的显著性声明；独立确认结果单列。

128个环境及策略随机采样提供回合重复，但只有5–15个独立seed簇；第一阶段针对一个固定模型；第二阶段比较两个固定模型，各自仍只有一个训练seed，不能推断跨训练seed或真机效果，也不能证明某个训练随机化项单独带来了多少收益。

## 第二阶段：原随机化模型自动重放

第一阶段全部完成后，冻结 `randomized_replay_plan.json`。它逐项列出第一模型实际完成的条件、seed和环境数，包含追加样本和独立确认样本。第二模型重放完全同一清单，不另选“更有利”的条件。

两个 checkpoint 的路径与 SHA256 都在 `lock.json.models` 中，评估途中不更换权重。环境样本和策略epsilon共用原文件；两模型输出保存在不同目录。已有完整任务可校验后跳过，结果文件也校验SHA256。

对比报告包含：

- 同条件最终成功率及增益（随机化模型 − 零随机化模型）和配对95%区间。
- 开启扰动造成的成功率下降减少了多少，扣除固定基准上的模型差异。
- 从完整随机化环境移除扰动带来的恢复是否减少，以及综合敏感性分数的变化。
- 曾成功但未保持、最终深度、XY误差、腕力的两模型对照表。
- 初筛与独立确认分别报告；区间跨零时不宣称明确提升。

类别评估覆盖全部5类；单项仅覆盖第一阶段实际细分的类别。这是同一测试集上的两个已训练模型比较，不是对原随机化模型重新做自适应筛选，也不是逐项重训因果实验。

## 耗时和规模

这不是训练，是推理评估。本次128环境完整预检实测约70秒/任务（见 runtime_estimate.json）。以下是第一阶段估算：

- 不追加seed：初筛60任务；单项增加20–50任务；独立确认50任务，总计130–160任务，约2.5–3.1小时纯仿真，建议预留3–5小时。
- 两阶段都追加至15seed：共290–380任务，约5.6–7.4小时纯仿真，建议预留6–10小时。

第二模型重放相同数量任务，整个两模型实验约为上述时间的两倍：通常预留 **6–10小时**；全部追加到上限时预留 **12–20小时**。纯仿真实测外推分别约5.1–6.2小时和11.3–14.8小时。

只串行运行一个仿真进程，避免并发争抢GPU使对比不稳。启动时间、GPU占用和IK重试会影响耗时。单条件初筛640回合，追加后最多1920回合；入围条件另外确认640回合，合计最多2560回合，具体表格显示实际N。

## 输出

- `RESULTS.md`：第一模型敏感性结论、类别表、单项表、独立确认及失败表现表，并链接第二阶段报告。
- `MODEL_COMPARISON.md` / `model_comparison.json`：两模型同条件成功率、敏感性改善与诊断表。
- `randomized_replay_plan.json`：第二模型严格复用的第一阶段任务清单。
- `results_randomized/`：第二模型原始结果，结构与 results/ 一致。
- `model_comparison_episodes.csv`：两模型全部逐回合数据，包含 model/condition/seed/env_id。
- `group_screen.json` / `factor_screen.json` / `confirmation.json`：结构化统计及排名。
- `results/<condition>/seed_<seed>/`：配置、命令、日志、样本指纹、实际初始状态和逐回合结果。
- `episodes.csv`：所有完成回合，包含condition/seed/env_id，便于复核配对。
- `preflight/`：开发时小规模物理预检，完全不计入正式统计。
