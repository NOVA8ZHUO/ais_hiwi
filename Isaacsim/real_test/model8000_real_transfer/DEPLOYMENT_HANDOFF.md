# 给真机电脑 Codex 的部署交接文档 — model8000

## 1. 目标、当前状态和入口

用户希望把已经训练的Franka轴插入策略迁移到另一台真机电脑，完成驱动适配与实机调试。主候选为本目录model8000，不是旧model2999，也不是model820。不要继续训练或修改奖励来代替部署工作。

本包已完成：原始检查点、独立CPU/GPU TorchScript actor、固定归一化统计量、LSTM推理包装、原始配置/代码快照、序列一致性验证及仿真评估资料。
本包尚未完成：真实机器人驱动、坐标标定、外力信号映射、实时控制适配、真实插入深度/松爪判断、实机验证。不要把“模型加载成功”报告成“真机部署成功”。

目标电脑Codex应先阅读本文、OBSERVATION_ACTION.md、params/env.yaml及本包源码快照；检查当地已有机器人代码和运行方式，复用可用接口。无需再次询问已明确的20N持续夹紧、固定base等偏好。未确定的机器人IP、驱动、坐标和反馈单位必须从本机配置或用户处取得，不能编造。

## 2. 文件与模型身份

- model_8000.pt：完整RSL检查点，含actor/critic/优化器。实机推理不需要critic或优化器。
- policy_actor.ts：推荐部署入口，已包含8000的观测归一化。切勿替换成2999的导出文件或归一化数据。
- runtime/policy.py：单机器人Policy包装，只有推理，无机器人指令。
- reference_test_vectors.pt、runtime/test_vectors.py：200步序列与回合reset验证。
- inference_validation.json：与原RSL ActorCriticRecurrent加载8000权重后的均值输出比较；batch1/4各200步含部分reset，最大误差0。
- params/、source_snapshot/、experiment_manifest.json：训练配置与源代码来源；保留只读，真机修改放在新目录real_adapter/。
- evaluation_reference/：8000的多种子、GUI轨迹分析、20/25/30秒定向实验资料。
- real_config.template.json：待填真机配置，null不是0，不能静默使用默认替代。
- SHA256SUMS.json、verify_package.py：搬运完整性校验。
- build_export_reference.py：训练电脑上的导出过程参考，含原机器路径；目标电脑不必运行，不能当部署启动脚本。
- background/：项目背景和实验记录，供追溯，不是待执行命令列表。

SHA以inference_validation.json与SHA256SUMS.json为准。原训练路径记录在experiment_manifest中；搬运后不能依赖那些绝对路径。USD资产存在外部引用，本包不是离线Isaac Sim安装镜像；实机推理不需要USD。

## 3. 目标电脑首先执行的离线检查

进入搬运后的本目录。建议使用独立Python环境；来源Python3.11、PyTorch2.7.0，CPU推理可用，不要求安装Isaac Sim、IsaacLab、RSL-RL或完整pip freeze。目标电脑已有可用PyTorch时先测试，缺依赖再按其CPU/CUDA条件安装requirements-inference.txt。不要改动机器人原有驱动环境。

```bash
python3 verify_package.py
python3 runtime/test_vectors.py
```

预期分别输出“All packaged files verified.”和“PASS sequence/reset inference”。这两步不会发送机器人命令。runtime/policy.py直接运行会用全零假观测，仅为加载演示，输出不可用于机器人。

调用示例（放在包根目录运行）：
```python
from runtime.policy import Policy
policy = Policy(device='cpu')
policy.reset()                     # 每个真实回合开始一次
# obs29必须由真实反馈和下面的状态逻辑构建
# action5 = policy.step(obs29)      # 每个策略周期只调用一次
```

不需要训练模式，不采样探索噪声，不更新归一化统计，不重复归一化。每回合维持LSTM h/c；不能每步reset，也不能为日志或“试算”重复调用step而推进隐藏状态。暂停后如何恢复需定义；未确认期间不要让旧动作无限保持。

## 4. 真机端先盘点这些实际接口

记录到real_adapter/HARDWARE_DISCOVERY.md：

1. 机器人型号、驱动/SDK与版本、网络配置、现有可用启动命令、支持关节力矩还是笛卡尔阻抗/位姿接口、控制频率和线程限制。
2. 7轴q/dq、末端位姿、雅可比、外力/外力矩、时间戳的来源；每个量的单位、参考系和实际刷新率。
3. hand对应真实机器人哪个link；法兰、工具TCP、panda_hand之间固定变换。不要把驱动EE位姿直接当panda_hand。
4. 外力是否已重力补偿/工具补偿；是环境作用于机器人还是机器人作用于环境；力作用点在哪里。
5. 夹爪宽度、抓取状态、持续抓取力指令的语义；正常停止、通讯丢失处理以及松爪接口。
6. 孔口如何定位、base是否牢固固定、轴尺寸及夹持方式是否与仿真一致。
7. 现有独立机器人限位、停止机制与反馈过期处理。沿用真实系统已有机制，不把仿真限力当硬件保证。

这些接口是部署依赖，不要擅自假定ROS版本、topic名称、机器人IP或libfranka接口。若本机已有完整驱动，可直接开展适配与离线验证，不要停在只给计划。

## 5. 坐标与标定

约定W为策略公共坐标系（Z向上、与训练任务方向一致），B为真实机器人base，H为训练意义上的hand。使用明确的T_WB、T_BH、T_H_TCP，记录矩阵方向和四元数顺序。

虚拟TCP：p_W_TCP = p_W_H + R_W_H * t_H_TCP。
位置输入：delta = p_W_TCP - p_W_hole，而不是反过来。
姿态输入：q_W_H，wxyz，单位四元数。驱动若为xyzw必须重排。四元数q和−q代表同一姿态，但网络未必同响应，初始化符号应匹配训练姿态分支，之后保持连续。
线速度输入：每15Hz策略周期的虚拟TCP位置差分（首步0）；角速度为H在W中的角速度，不是欧拉角速度。雅可比和空间速度必须对应同一参考系/作用点。

仿真hand→虚拟TCP平移为[-0.0007295087,-0.0013625964,0.1732249624]m，仅参考，真机需标定。建议在真实20N抓取后测轴底相对H的变换，并多次抓取记录分布。区分固定标定与抓取后滑移：不要把实时测得真实轴底偷偷替换进原虚拟TCP观测。
孔口位置是开口平面中心，不是孔底。固定base后可使用一次标定坐标。误差±10mm是训练随机化范围，不是要求真机加上误差。

控制目标姿态按W中roll=π、pitch=0、yaw=参考yaw构造。若W与真实B不同，目标姿态、位置、速度、力、雅可比必须一致转换。仅把位置改成相对孔坐标却不处理姿态/力，会破坏接口。

## 6. 29维观测合同（float32，15Hz）

|索引|数量|输入与单位|
|---|---:|---|
|0–2|3|虚拟TCP−估计孔口位置，W系，m|
|3–6|4|hand姿态，W系，wxyz|
|7–9|3|虚拟TCP相邻策略步差分线速度，W系，m/s，首步0|
|10–12|3|hand角速度，W系，rad/s|
|13–15|3|轴与base接触净力代理，W系，N|
|16|1|接触阈值参数，训练每回合5–8N，实机配置值须记录|
|17–21|5|上一策略步clip至[-1,1]的5维动作，首步0；不是阶段限制后的执行目标|
|22|1|名义轨迹phase，见下式|
|23|1|夹爪两指总宽度，m|
|24–27|4|SETTLE/SEARCH/PROBE/INSERT的one-hot|
|28|1|releasing标志0/1|

phase=clip(max(elapsed−1.0,0)*0.008/(0.0192845565+0.047),0,1)。这是名义进度，不是真实插入深度，也不是elapsed/episode_timeout。延长到25秒不应拉慢名义轨迹。

训练位置噪声std0.00025m（也进入差分速度），力噪声std1N。真实输入不要机械重复叠加噪声。孔偏差每回合固定XYZ±0.010m；抓取偏差hand系X±0.008m、Y0、Z±0.005m，真机不需要主动制造它们。

完整检查53维critic观测只用于训练，真实轴姿态、真实孔误差等特权量不用给actor。不要为凑53维而用0冒充真值。

## 7. 力反馈的关键对齐

仿真contact_force来自shaft对base筛选接触对的force_matrix求和；筛选是对象过滤，不是时间低通。它排除夹指接触。actor还叠加力噪声，阶段逻辑和控制中的contact_force则没有这项人工噪声。

真机六维腕力/机器人估计外力不是自动等价：需要标定空载偏置、工具及所夹轴重力、坐标旋转、符号，并评估运动惯性与滤波延迟。若接口是关节外力矩，不能直接当三维力，要使用驱动提供或经过验证的外力估计。姿态变化时工具重力补偿也要变化，不能只在一个姿态清零。

用轻微接触验证：向下接触孔口时，供阶段判定的W系Fz应对应向上的正反力；XY方向响应也应一致。原始与补偿后的信号都记录。新加低通滤波必须记录带宽/延迟，不能声称与训练完全一致。

## 8. 动作输出与控制移植

输出5维均值动作并clip[-1,1]：XYZ残差、yaw请求、成功预测。前3维名义位置尺度[0.020,0.020,0.002]m；yaw尺度π/4；第五维映射(a4+1)/2仅预测，不直接控制机器人或松爪。

动作不是关节角，也不是直接力矩，更不能把a_z直接当牛顿。应移植以下代码的执行语义：
- source_snapshot/forge_shaft_insert/mdp/forge_paper.py：process_actions、apply_actions、hold_gripper、reset、actor_state。
- source_snapshot/forge_shaft_insert/mdp/insertion_supervisor.py：完整阶段状态机。
- 同目录被导入的参考限速/死区函数；以源码调用顺序为准。
- params/env.yaml：历史最终参数；不要仅看配置类默认值。

策略15Hz，仿真底层240Hz。真机使用驱动要求的高频控制线程；Python策略不承担要求硬实时的力矩循环。高频使用真实dt，实现相同参考状态积分/阻尼/限幅语义。不同接口产生的响应差异要测试记录，不能用15Hz位置跳变替代高频阻抗后宣称完全复现。

关键参数：
|项目|仿真设置|
|---|---|
|参考平移速度/加速度上限|0.012m/s、0.040m/s²，向量范数|
|参考yaw速度/加速度|0.5rad/s、1.5rad/s²|
|平移Kp随机范围|400–800N/m；实机须明确选值|
|平移阻尼|2sqrt(Kp)，依原实现；不是已标定真机最优阻尼|
|XY弹簧力死区|每轴随机0–5N；只影响XY弹簧项，不影响Z或阻尼|
|目标相对当前TCP限制|每轴16–25mm随机；不是动作尺度|
|SEARCH接触后下压|3N|
|PROBE/INSERT下压请求|2+(a_z+1)/2*(4−2)N，范围2–4N|

|下行速度衰减尺度|0.008m/s|

仿真关节控制为J_TCP转置乘笛卡尔wrench加重力补偿。真机若驱动已有重力/科氏项补偿，核对后避免重复补偿。所有7个机械臂关节参与控制，没有锁死末端几个关节。不要擅自焊住轴、强制轴竖直或消除真实滑移。

## 9. 阶段、夹爪、时序与reset

状态机：SETTLE=0、SEARCH=1、PROBE=2、INSERT=3。
- 初始夹紧稳定1s，且宽度有效后SEARCH。
- SEARCH中Fz≥1N连续2个策略步且冷却结束，进入PROBE并锁当前XY和参考yaw。
- PROBE相对anchor下降≥3mm且横向净力<2N连续2步，进入INSERT。
- SEARCH也可按估计TCP低于估计孔口16mm、相对anchor下降>3mm、横向力<2N连续2步直接进入INSERT。
- PROBE超0.8s未确认则回SEARCH，冷却0.4s。
- PROBE/INSERT锁XY/yaw，Z仍力控制；当前INSERT没有停滞退出机制。部署第一版不悄悄新增恢复逻辑，若新增需作为独立版本。

每策略周期：读取同一时刻反馈→用上一周期动作/阶段和当前elapsed构建观测→调用一次policy→保存裁剪动作→按源码更新松爪/阶段/目标并增加elapsed→高频控制执行；下次观测再反映更新后的阶段。新回合清LSTM、上一动作、计时、差分位置缓存、参考速度、下压力状态、supervisor计数及松爪状态。真实reset需移动到已确认孔上方并抓好轴，不能模拟式瞬移。

用户明确要求：持续给20N夹紧指令，总闭合速度20mm/s，预期宽35mm，容差±5mm；达宽后仍持续夹紧。真机两指机械耦合等位移，允许轴真实抓取不对称及接触滑移/旋转，不能以两个手指独立横移模拟真实误差。确认SDK的force参数语义，仿真每个滑动指施加20N并不意味着应给真机40N。避免反复提交会取消/重启grasp的异步命令；使用能维持抓取力的驱动机制并验证。

## 10. 结束与松爪：不能省略的真机替代

仿真成功：真实轴底进入孔口≥25mm且位于目标孔区域（XY半径13mm），不要求严格倾角；随后松爪开到60mm，观察2s后release_complete。严格落座另统计深度46–48mm、XY≤0.5mm、倾角≤5°，不是松爪前置条件。

真机没有仿真轴底真值。需要可验证的进深/有效入孔估计；轴滑移时不能把固定虚拟TCP深度无条件当轴底深度。优先使用实际可用的视觉/几何测量与位移接触历史；未实现可信判断时使用人工确认松爪，并在日志标识，不能用第5维成功预测偷偷自动放开。

原仿真20s超时。8000定向延长试验：8例历史浅插失败25s救回6例，6例均22.20–24.27s完成松爪严格落座；30s仍6/8。前20s轨迹完全匹配。另22例未有效入孔失败未测试，不代表整体25s成功率。实机可把25s作为明确记录的调试候选；不改变phase公式，保持2s松爪观察语义，记录超时是否发生于松爪观察期。

仿真还按真实轴底越界及宽度失败结束；真机用可获得的状态独立实现边界/反馈失效/机器人故障停止，不假装有真实轴底真值。宽度在1.5s后检查35±5mm，松爪期间豁免此抓取检查。超时/失败不要自动执行未经定义的回撤或松爪动作，调用当地已明确的停止/保持行为。

## 11. 目标电脑实施顺序与交付物

1. 校验包并跑序列测试；发现本机驱动和状态接口，完成HARDWARE_DISCOVERY.md。
2. 填real_config.json的必需字段，保留单位/坐标/标定日期与来源；禁止null默认为0。Kp/死区/阈值等从训练范围选择的值须标为调试选择，不是测量结果。
3. 实现real_adapter中的状态采集、坐标转换、观测组装、LSTM策略调度、阶段逻辑和控制器适配。先用录制状态离线回放验证，与包内源码逐步对照状态切换/限幅。
4. 在真实机器人状态上运行不发送动作的观测/策略日志，检查静止速度、孔偏差、力零偏、四元数及时间戳。测试零动作不等于零运动：零残差仍有名义下插/接触下压，不能称为保持模式。
5. 使用已验证的驱动与现场操作条件，先核对无接触跟踪及力方向，再执行插入调试。代码/标定可自主完成；缺少关键硬件信息时说明具体缺项，不凭假值运动。
6. 输出真实运行命令、配置快照、模型SHA、每回合日志和DEPLOYMENT_STATUS.md，清楚区分已验证和待验证。

最终应有：read_state、build_observation、policy runner、stage/controller adapter、夹爪适配、明确结束与reset逻辑、日志/回放工具。这里描述接口职责而非假定某SDK函数名。本包没有可直接连接未知机器人的“一键运动命令”，目标Codex需要基于当地驱动生成。

## 12. 日志与验收证据

每策略步记录单调时间戳、反馈年龄、完整obs29、raw/clipped action5、LSTM reset事件、阶段/切换原因、虚拟TCP/估计孔/可用真实轴底估计、原始与补偿力、实际速度、参考目标、指令力、宽度、进深估计、松爪状态。高频控制另记录速度峰值/力峰值，标记采样频率。
每回合记录成功25mm、是否人工确认、是否松爪、是否落座、超时/故障原因、首次入孔时间、最长无进展时长、P95/峰值力、动作饱和率、各阶段时长。成功率分母按独立回合，不能按帧数。报告真实观测证据不足的指标为不可测，不填0。

部署通过至少包括：迁移校验和序列推理通过；状态单位与坐标验证；连续夹紧符合要求；动作语义及阶段锁定一致；底层反馈/控制时序与限幅可追溯；松爪判断来源明确；真实完整回合有日志。仿真成功率不是实机验收阈值。

## 13. 已知策略表现与局限
