# 实验登记与调整记录

## 记录规则（从本轮开始自动执行）

每次通过scripts/train.py训练，run目录保存：

- `params/env.yaml`、`params/agent.yaml`：实际环境、奖励/控制参数和PPO参数。
- `source_snapshot/`及`experiment_manifest.json`：训练启动时项目源码/文档副本、SHA256、命令参数、开始/结束时间与状态；可用环境变量`FORGE_EXPERIMENT_NOTE`记录调整动机。
- `training_console.log`：环境创建开始后的Python stdout/stderr，不承诺覆盖Kit原生输出。
- 原始TensorBoard事件，以及结束时完整导出的`metrics_scalars.csv`：所有已记录scalar、iteration、时间戳，不只最后一轮。
- `episode_metrics.csv`：所有环境所有已完成回合；`episode_metrics_control_trace.csv`：默认前4个环境每个15 Hz控制步的诊断记录，包含reset前最后一步。
- `experiment_summary.json`：最终scalar、真实回合数/成功率/终止原因。强制kill/断电可能来不及最终导出；原始事件与已flush的CSV仍可用归档脚本补导。

控制trace包括：实际经过时间、下插相位、动作是否启用、轴/虚拟TCP/请求目标/平滑参考相对真实孔位置、轴相对hand的Y倾角、参考与实际TCP速度、最后物理步的力命令、采样接触力、5维动作、hand四元数、7关节位置/速度、夹宽和终止原因。坐标向量0/1/2对应世界xyz，轴误差z的负值表示插入深度；command_force_2<0表示向下命令。该trace不能恢复每个240 Hz物理步的接触尖峰。

历史7次有TensorBoard事件的训练均已补导所有scalar和摘要，原始checkpoint/config/episode CSV保留，索引在logs/rsl_rl/forge_shaft_insert_residual/experiment_index.json。历史缺少的控制轨迹、源码快照和终端文本不能凭空补回；不把当前源码冒充历史源码。

## 为什么可能在孔口又拖走

1. 未锁定后几个关节：7个panda_joint均参与Jᵀ力矩控制。但hand目标roll固定180°、pitch固定0，策略只有xyz+yaw，无法主动输出pitch修正。姿态环纠正的是hand，不是已经在夹爪里转歪的shaft。
2. Actor不直接观察真实轴姿态，只有虚拟TCP/hand姿态/力等；critic和奖励能看到真实轴倾斜。倾斜惩罚可以鼓励避免撞歪，不能凭空增加纠偏执行自由度或精确轴姿态观测。
3. 没有接触后锁定XY再插入的阶段逻辑。每个控制步的XY残差都可变化；到孔口不会自动停止横向搜索。
4. 下插是位置目标轨迹，不是恒定向下力指令。Z残差±25 mm可抵消或反转名义下插；零残差的名义下降量每步仅0.533 mm。
5. 三维参考总速度上限20 mm/s，是每个控制步最多约1.33 mm的参考位移量级，对0.5 mm径向间隙仍可能较大；它不是实际TCP速度的硬上限。
6. 保留每轴0–5 N力死区：静态近似下5 N/Kp相当于6.25–12.5 mm位置误差才克服最大死区。10 N合力上限由XYZ共享，横向力也可能占据预算。是否实际发生由trace确认，不能仅凭肉眼断言。
7. 多数回合约3秒就越界，名义下插约8.79秒才到最终目标；回合根本没有走完整个下插过程。

后续建议按单因素实验：先定位越界方向与Z目标/力；再决定是否处理提前失败的回报漏洞、接触阶段的横向移动和Z进给，最后评估是否确实需要受限roll/pitch动作及可部署的轴姿态估计。不要同时改这些项，否则无法判断改善来自哪里。


## 最新证据：本轮model_19确定性回放

使用当前相同物理/奖励设置、seed42、4环境、100控制步，无探索噪声；这不是原GUI训练轨迹的重建。

- 完成11个回合，11次都是XY越界，0成功；全部完成回合的轴–Base采样接触力为0。
- 越界时轴主要偏向世界+Y约98–108 mm；XY距离超过100 mm。
- 参考速度上限得到遵守，最大约0.020 m/s；Jqdot记录的实际TCP瞬时速度最大0.659 m/s，相邻控制步位置差得到的平均速度最大0.184 m/s，交叉印证实际运动并没有被20 mm/s硬限制。
- 越界时Y参考位置相对孔约3–19 mm，实际TCP偏到约99–108 mm，Y力命令已经约−9.1至−10 N反向作用。这不是仅靠降低策略目标速度就能解释的情况，需要优先检查闭环跟踪、姿态耦合和合力限幅对阻尼的影响。
- 有效运动样本中向下Z力约37.9%、接近0约23.9%、向上约38.2%；向下最大约2.50 N。确实不是持续下压，但本次没有进入定义的近孔窗口（XY<2.5 mm且|Z|<5 mm），不能据此断言原GUI每次“孔口拖走”时的具体因果。
- 7关节位置/速度均已记录；仍未增加roll/pitch策略自由度。

**更新判断：**提前终止减少负奖励是可能的训练目标漏洞，但不能将所有越界归为策略主动选择；回放显示明显闭环跟踪问题。建议暂停直接扩大到200轮，先验证固定目标下的稳定性、yaw运动时的位置保持以及实际速度，再处理奖励/阶段逻辑。此次只增加记录和诊断，不修改控制/奖惩参数。

## 分阶段下插修复（进行中，2026-09-28）

用户要求修复跟踪、持续下压、到孔口后被横向拖走，并核实reset夹持状态。

1. 单因素阻尼对照：Kp600、摩擦0.8、无抓取/孔误差，无下插。保持和yaw分别比较姿态Kd=10.954与0.5。旧yaw组峰值采样TCP速度0.536 m/s、6秒内3次重置；新yaw组0.00542 m/s、位置偏移0.430 mm、0重置。新保持组峰值0.00127 m/s、位移0.355 mm。支持过大的显式姿态阻尼是振荡主要来源之一，不把问题单归因于RL。保留转动Kp30，Kd独立改为0.5 Nm·s/rad；7个关节仍参与力矩控制。

### 初始几何与接触搜索补充

第一版分阶段零残差试验4回合全部超时、没有越界/夹宽失败，但未插入；接触后真实轴底逐渐横偏，不能把运行PASS称为成功。发现旧reset轴姿态继承约0.94°倾斜，且标称轴底与固定虚拟TCP存在约0.2/0.6 mm确定性偏差。新标称reset设轴竖直、轴底位于离线FK虚拟TCP；用户x±8/z±5 mm随机误差继续叠加，只改标称初始状态，不在接触后强制居中或锁轴。
首次接触后即使恢复SEARCH，也使用1.5 N轻压，不再让时间推进的位置目标积累到8 N硬顶；PROBE/INSERT仍默认3 N，Z动作调节2–4 N。
核查早期阻尼对照脚本发现，仅修改task摩擦范围未同步已实例化的材质事件，因此早期对照实际摩擦仍随机0.5–1.0，不能当作严格单因素结果。脚本已修正材质事件，待以固定0.8摩擦重复验证；旧结果保留，不覆盖。


竖直初始轴+轻压搜索仍出现孔沿停滞。4环境在t=1秒时实际轴底−虚拟TCP的世界Y偏差分别约0.88、1.39、1.38、1.39 mm（轴倾角约0.1°，不是大倾斜）。据此将固定hand→标称轴底变换的局部Y从−0.1126 mm调整为−1.3626 mm，补偿平均1.25 mm标定偏差；初始shaft实际姿态/位置保持上一试验值。该变换不是每回合用真实轴更新，仍保留抓取随机误差与接触偏差，也不强制两指对称。属于仿真标称夹持标定，真机仍需替换为实测变换。
